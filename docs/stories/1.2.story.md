# Story 1.2: 基于角色的登录默认路由优化

## Status
Approved

## Story
**As a** "成员"或"编辑"角色的系统用户，
**I want** 登录成功后自动跳转到探索页面(`/explore/apps`)，
**So that** 我可以立即开始浏览和使用AI应用，提升工作效率。

## Acceptance Criteria
1. **"normal"（成员）角色**用户登录成功后，自动重定向到 `/explore/apps` 页面
2. **"editor"（编辑）角色**用户登录成功后，自动重定向到 `/explore/apps` 页面
3. **其他角色**（如管理员）保持现有的登录后跳转行为不变
4. 重定向过程无明显延迟或闪烁现象
5. 现有登录功能和角色验证逻辑继续正常工作
6. 探索页面内的权限控制保持原样（页面内容的权限不变）
7. 新的重定向逻辑遵循现有Next.js路由和角色管理模式
8. 与用户权限系统的集成保持当前行为，仅修改跳转目标
9. 变更通过适当的测试覆盖，包括不同角色的测试用例
10. 相关配置文档更新（如有需要）
11. 验证现有功能无回归问题，特别是其他角色的登录行为

## Risk Assessment and Mitigation

### 风险评估
- **主要风险**：可能影响管理员等其他角色用户的预期登录行为
- **风险等级**：低
- **影响范围**：仅涉及登录后重定向逻辑，不影响核心业务功能

### 缓解措施
- **精准范围控制**：明确限定仅修改"normal"和"editor"角色，其他角色保持不变
- **渐进式测试**：先在测试环境验证各角色行为，再部署到生产环境
- **监控机制**：部署后监控各角色用户的登录后行为，及时发现异常

### 回滚方案
- **简单回滚**：恢复原有基于角色的重定向配置
- **回滚复杂度**：极低，主要是配置或简单逻辑变更
- **回滚时间**：预估5分钟内可完成回滚

## Integration Requirements
- **认证系统兼容性**：必须与现有认证流程完全兼容
- **角色系统集成**：必须正确读取和响应用户角色信息
- **路由系统集成**：必须遵循Next.js App Router的重定向最佳实践

## Performance Impact
- **预期性能影响**：无或可忽略不计
- **原因分析**：仅修改重定向目标，不增加额外的计算或网络请求
- **监控指标**：登录响应时间保持现有水平

## Dev Agent Record

### 实际修改文件
**主要修改文件**: `/web/app/page.tsx`
- **位置**: Line 114 (在 isLimitedUser 条件块内)
- **修改前**: `router.push('/datasets')`
- **修改后**: `router.push('/explore/apps')`
- **修改原因**: 将限制用户(normal和editor角色)的默认重定向从数据集页面改为探索页面

### 关键代码变更详情
```typescript
// 修改前
if (isLimitedUser) {
  // 普通用户和编辑者跳转到数据集页面（知识库功能）
  router.push('/datasets')
}

// 修改后
if (isLimitedUser) {
  // 普通用户和编辑者跳转到探索页面
  router.push('/explore/apps')
}
```

### 技术分析结果
1. **重定向逻辑位置确认**:
   - 登录重定向在 `/web/app/signin/normalForm.tsx:39` 和 `/web/app/signin/components/mail-and-password-auth.tsx:76`
   - 实际角色基础路由在 `/web/app/page.tsx:114` (主页面组件)

2. **角色判断逻辑确认**:
   - `isLimitedUser` 定义在 `/web/context/app-context.tsx`
   - 逻辑: `currentWorkspace.role === 'normal' || currentWorkspace.role === 'editor'`

3. **实现策略**:
   - 修改主页面路由逻辑而非登录重定向
   - 保证其他角色('owner', 'admin', 'dataset_operator')行为不变
