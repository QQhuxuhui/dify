# Epic 1.3: 探索页面工作区交互逻辑重设计

## Status
Ready for Story Development

## Epic Goal
重设计探索页面的工作区交互逻辑，移除点击后聊天全屏的默认行为，改为实现工作区向左压缩隐藏和右侧内容区域向左扩展的新布局模式，提供更直观的空间管理体验。

## Epic Description

### 现有系统上下文
- **当前相关功能**：探索页面点击工作区元素会触发聊天区域全屏显示
- **技术栈**：Next.js 15.2.3 + React 19 + TypeScript + Tailwind CSS，使用ChatWithHistoryContext管理全屏状态
- **集成点**：探索页面工作区点击事件、ChatWithHistoryContext状态管理、布局响应系统

### 增强详细信息
- **移除的内容**：取消点击工作区元素后聊天区域自动全屏的逻辑
- **添加的内容**：实现点击工作区元素后工作区向左压缩隐藏，右侧区域向左拉伸占满浏览器的新交互模式
- **集成方式**：修改现有点击事件处理逻辑，重新设计布局状态管理，实现工作区隐藏/显示切换
- **成功标准**：点击工作区元素时，左侧工作区平滑向左压缩隐藏，右侧内容区域自动向左扩展填满可用空间

### 深度技术架构分析

#### 双层布局架构
```
/explore/apps页面
├── Explore组件 (外层布局)
│   ├── Sidebar (工作区列表)
│   └── 右侧内容区 (w-0 grow)
│       └── AppList → InstalledApp → ChatWithHistory (内层布局)
│           ├── ChatSidebar (聊天历史)
│           └── 聊天区域
```

#### 现有状态管理层级
1. **ExploreContext** - 控制工作区应用列表状态
2. **ChatWithHistoryContext** - 控制聊天侧边栏和全屏状态

#### 核心技术挑战
- 当前`isFullScreenMode`控制的是**内层聊天组件**的全屏
- 用户需求是控制**外层工作区**的显示/隐藏
- 这涉及跨组件层级的状态协调和布局重构

## Stories

### Story 1.3.1: 扩展ExploreContext工作区状态管理
**目标**：添加工作区显示/隐藏状态到ExploreContext，支持工作区列的显示控制

**技术要点**：
- 扩展ExploreContext添加`workspaceCollapseState`状态
- 实现Explore组件的工作区Sidebar显示控制逻辑
- 确保与现有ExploreContext功能完全兼容

**验收标准**：
- ExploreContext成功添加工作区隐藏状态管理
- Explore组件响应新状态正确隐藏/显示工作区Sidebar
- 现有探索页面功能保持完全正常

### Story 1.3.2: 重构InstalledApp交互触发机制
**目标**：移除ChatWithHistory自动全屏触发，添加向上传递工作区隐藏状态的机制

**技术要点**：
- 移除InstalledApp中的ChatWithHistory自动全屏逻辑
- 实现InstalledApp到Explore的状态传递机制
- 修改点击事件处理，触发工作区隐藏而非聊天全屏
- 保持聊天功能本身完全不变

**验收标准**：
- 点击工作区元素不再触发聊天全屏
- InstalledApp成功向Explore传递工作区隐藏请求
- 所有现有聊天功能保持完全正常
- 跨组件状态传递机制工作正确

### Story 1.3.3: 优化布局响应和动画效果
**目标**：实现工作区Sidebar的平滑隐藏动画，配置右侧内容区域的自适应扩展效果

**技术要点**：
- 实现工作区Sidebar的平滑隐藏/显示动画
- 配置右侧内容区域的自适应扩展效果
- 确保两级布局系统协调工作
- 添加用户友好的状态切换控制

**验收标准**：
- 工作区隐藏/显示有流畅的动画过渡
- 右侧区域能够平滑扩展至全屏宽度
- 布局切换过程中无闪烁或异常
- 用户可以便捷地切换工作区显示状态

## Risk Mitigation

### 风险评估
- **主要风险**：可能影响现有聊天全屏功能或探索页面的现有用户体验
- **风险等级**：中高（跨组件架构修改）
- **影响范围**：探索页面的布局系统和用户交互流程

### 缓解措施
- **架构保护**：基于现有ChatWithHistoryContext架构扩展，保持现有聊天功能完全不变
- **渐进实施**：分阶段实施3个故事，每个故事都有独立的回滚方案
- **测试覆盖**：全面测试跨组件状态协调和布局响应
- **用户体验保护**：确保新交互逻辑直观易用，不破坏用户习惯

### 回滚计划
- **Story 1回滚**：移除ExploreContext中的新增状态管理代码
- **Story 2回滚**：恢复原有的InstalledApp点击交互逻辑
- **Story 3回滚**：移除动画和布局扩展相关的CSS和逻辑
- **整体回滚复杂度**：中等，主要涉及状态管理逻辑的恢复

## Performance Considerations

### 性能优化要点
- **状态管理优化**：使用React Context的最佳实践，避免不必要的重渲染
- **动画性能**：使用CSS transform而非layout属性实现动画，利用GPU加速
- **组件渲染优化**：确保跨组件状态更新不触发大范围重渲染

### 性能监控指标
- **布局切换响应时间**：<100ms
- **动画帧率**：保持60fps
- **内存使用**：不增加显著内存占用
- **页面加载性能**：不影响探索页面的初始加载速度
